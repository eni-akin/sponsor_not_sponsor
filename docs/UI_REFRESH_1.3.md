# SNS 1.3 UI refresh

October 31 closeout: the local inbox recovery, independent/stale cleanup-health
feedback, readable duplicate/history summaries, and documented text/target sizes
are implemented and covered by expanded regressions. Current exact candidate and
fresh verification are in the [1.3 release worksheet](../release/RELEASE_1.3.md).
Its hash supersedes the October 30 candidate below. The authorized Worker/site
rollout and fictional-test cleanup are verified in the
[rollout checkpoint](UI_REFRESH_ROLLOUT_2026-10-31.md). Store 1.3 still requires
final approval and manual owner dashboard action.

The local 1.3 candidate refines the approved light SNS identity across the
popup, injected evidence panel, help/privacy documents, public website and
reporting surfaces. See the design-system master for the component inventory
and tokens. Sponsorship interpretation and reporting API/database contracts
are unchanged.

Reporting uses numbered import, explanation and review sections, inline
validation, a linked error summary and explicit loading feedback. Confirmed
submission navigates to a dedicated receipt page with copy feedback; its
one-time session transfer contains only receipt ID and receipt time. A missing
or expired transfer never claims submission.

The inbox uses a responsive list/detail workspace, structured report fields,
collapsible diagnostic JSON, list loading/empty/error states, and disabled
destructive actions until the typed ID matches. Server revision and confirmation
checks remain authoritative.

Release gates: inspect screenshots and exact 1.3 ZIP, verify all affected suites,
then deploy admin followed by public form and receipt assets, verify production,
and publish matching website pages. Store submission requires explicit final
release approval. No screen-reader pass is claimed.

The existing submitted 1.2 package must remain intact. No production deployment,
Store submission, push, or private production report retrieval is recorded by
this implementation note.
