# Laya training initialization and research

October 5, 2026 (America/Chicago).

## Result

The first full-model optimizer smoke update completed locally on Apple MPS. The cached multilingual checkpoint contains **321,908,995 parameters**. Both encoder and decision-head parameters changed, gradients were finite, the new checkpoint reloaded with identical raw probabilities, and SHA-256 checks confirmed all base artifacts stayed unchanged.

This engineering checkpoint uses two authored examples (ten decisions). It is uncalibrated and is not a validated sponsorship model. The smoke performs one accumulated AdamW update. It does not provide a general multi-epoch domain trainer or resumable optimizer state.

- [Recorded run](runs/smoke-2026-10-05-01/report.json): versions, source/base hashes, losses, and predictions.
- Local checkpoint: `.model-cache/training/smoke-2026-10-05-01/checkpoint/` (ignored model artifacts).
- Run time: 15.652 seconds, including initialization, before/after checks, saving, and reload.
- Average uncalibrated cross entropy on the training fixtures: 1.44077 → 0.19997. This measures fit to the same examples, not unseen accuracy.
- A separate actual service-worker load check passed on CPU with all five existing answer fields.

## Research conclusions

**Start from the existing multilingual base.** This isolates training's effect against the current service baseline and preserves its context capability. Changing the backbone simultaneously would confound the comparison. The cached base revision is `e4e9ddf21a7b1903b7acffd8814ad4307bf63a67`. The typed-decisions checkpoint can be compared later; its unrelated benchmark scores do not establish job-policy quality.

**Use typed classifier training.** Upstream uses RLCD: noisy-logit policy-gradient learning plus soft cross entropy against target distributions. Its recipe separates encoder/head learning rates (2.5e-5 / 1e-4), uses AdamW, and clips gradient norm to 1.0. This smoke adapts those elements to one update. The one-hot targets are labeled as authored engineering targets, never teacher probabilities. [Official guide](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/docs/finetune.md).

**Local GPU training is feasible.** A probe outside the sandbox found working MPS and 17,179,869,184 bytes of unified memory. The previous CPU-only finding came from execution restrictions. Upstream's Apple Silicon trainer provides a single-process full-precision path. The inspected recipe is pinned to `8a6e1328cce2460a0e5aa348ad465bb1b5821cd2`, resolved using GitHub's API. We retained the installed runtime rather than upgrading production dependencies during this experiment. [Pinned Apple trainer](https://github.com/NandhaKishorM/laya/blob/8a6e1328cce2460a0e5aa348ad465bb1b5821cd2/notebooks/laya_finetune_typed_decisions_mps.py).

**Match the worker inputs exactly.** The script imports the actual service questions through Node and constructs the same title/employer/previous/TARGET/next state. It imports the worker's 8,192-token limit and 512-token header budget, rejects excessive state length, and checks distinct option token spans. The upstream demo's shorter budgets should not silently alter our task. Upstream's browser specialization example reports substantial effects from representation and truncation; this supports testing our input format, without transferring its browser-task scores to our product. [Browser specialization study](https://github.com/NandhaKishorM/laya/blob/main/docs/finetune_browser_agent.md).

**Keep the first question contract fixed.** `laya-policy-v1` asks scope, sponsorship, timing, CPT, and OPT per passage. The existing role-level prototype differs in both questions and labeling unit and cannot be used as a drop-in training set. Citizenship/export restrictions require a separate expanded-contract experiment. More training examples cannot create an absent output category.

**Calibrate separately after training.** Upstream persists temperatures and removes inherited per-option overrides that could mask the new fit. The installed runtime clamps temperatures, so a future calibration routine must use its actual bounds. This smoke exports neutral temperatures and marks calibration absent. No threshold is fitted from these fixtures. [Calibration persistence](https://github.com/NandhaKishorM/laya/blob/9d955671415fc19f069b9cc998928075c1f255ec/docs/finetune.md#calibration-is-part-of-the-run).

**Evaluate meaning as well as confidence.** An upstream reproduction reports confidently incorrect decisions for some negated cancellation instructions. That motivates sponsorship offer/refusal minimal pairs, exceptions, and scope tests; it does not establish the same failure rate on job postings. [Negation issue](https://github.com/NandhaKishorM/laya/issues/377). Another report finds confidence behavior varies with option count, motivating separate inspection of our 3-, 4-, and 6-option questions. [Option-count issue](https://github.com/NandhaKishorM/laya/issues/394).

## Initialization verified

1. Load the complete pinned checkpoint using `laya.load` and its strict architecture/weight loading; retain the pretrained decision head.
2. Work offline and hash weights, tokenizer/config, questions, worker, and trainer.
3. Use full precision, microbatch one, and encoder/head gradient checkpointing on MPS. Accumulate ten decision losses into one update. Seed Python, PyTorch, and MPS; cross-device bitwise reproducibility is not assumed.
4. Validate finite losses/gradients, clip gradients, verify both parameter groups change, and save into a new directory. Existing output directories are refused.
5. Save weights, tokenizer, encoder configuration, and decision configuration together. Reload and compare raw probabilities, then recheck base hashes.

This run used short sequences, at most 175 tokens. It does not establish memory capacity for 8,192-token backpropagation or full-dataset throughput. Measure actual token-length distributions and representative batches before estimating training duration. Keep MPS allocator safety limits enabled.

## Reproduce

From the project root, using the existing `.decision-venv`:

```sh
pnpm train:laya:smoke --output .model-cache/training/NEW_RUN --device mps
pnpm test:laya:smoke
pnpm test:laya:training
pnpm prepare:laya --worker-review --output evaluation/laya-training/NEW_REVIEW
```

MPS needs access outside the restricted execution sandbox. Set `LAYA_SMOKE_CHECKPOINT` to the absolute saved checkpoint directory when running `pnpm test:laya:smoke` to include the real worker-load regression; otherwise that test is explicitly skipped.

No paid compute, cloud account operation, dependency upgrade, model download, or publication was needed. The extension's default model and thresholds remain unchanged.
