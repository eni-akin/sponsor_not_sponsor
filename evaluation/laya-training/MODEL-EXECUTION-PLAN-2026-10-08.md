## 4. Resumable training

Extend `scripts/train_laya_smoke.py` only after the gate passes. Reuse its pinned multilingual revision, question loader, input encoding, finite-loss guard, full-model RLCD recipe, gradient clipping, checkpoint serialization, reload comparison and base-file hash preservation. Keep its authored-smoke behavior separately callable. Its present optimizer is deleted after one update: it is not a resumable trainer. Do not silently replace RLCD with a different objective.

Read only `train` records from validated manifests. Export `job_title`, `employer`, `previous`, `TARGET`, `next` exactly as `server/laya_worker.py` constructs them. Labels, rationale, URLs, family IDs and reviewer notes remain metadata. Recover genuine neighboring blocks from the same captured vacancy; never synthesize neighbors from unrelated passages. Missing posting neighbors must be explicit, and their production compatibility assessed before training. Reuse token/option guards so evidence cannot be truncated or criteria collapse. Preserve one-hot human targets; they are not calibrated distributions.

Record and pin seed, epoch count, learning rates, effective batch size/accumulation, RLCD exploration schedule and base revision before the run. Use epoch/optimizer-update boundaries for checkpoints to avoid resuming partially accumulated gradients. The checkpoint must retain model and AdamW state, epoch, next batch cursor/permutation, completed updates, scheduler/exploration progress, Python RNG, Torch CPU RNG, active accelerator RNG, and NumPy RNG if used. Persist actual runtime/package/device metadata and source/dataset/question/contract hashes. Resume refuses incompatible input/hash/hyperparameter drift; it must not reset exploration or optimizer moments.

Write checkpoints into new directories, then publish completion metadata atomically after files and hashes validate. Preserve failed attempts for diagnosis. Optimizer/RNG state is local trusted training state; do not load arbitrary user-supplied pickle artifacts. Cache/base weights remain unchanged.

Restore saved RNG state after model/optimizer initialization and loading, which can consume random draws. Keep actual domain-run progress separate from inherited upstream training statistics in checkpoint configuration; the existing smoke artifact retains upstream history alongside its own single update.

Small necessary check: compare a two-update uninterrupted run with a one-update checkpoint followed by resume on authored fixtures. Verify identical optimizer step/moments, permutation/cursor, RNG continuation, exploration value and parameters on deterministic CPU; accelerator predictions may use a declared numerical tolerance. Separately load the inference checkpoint through the existing JSON-lines worker and validate all five answer shapes. This test proves continuity; it cannot prove job accuracy.

## 5. Calibration

Freeze the selected training checkpoint before calibration. Use only independently verified calibration records; model parameters stay frozen. Read calibration records through identical worker state and question ordering and store raw logits/options alongside record/checkpoint hashes. All five product questions map to choice type 0. The installed runtime requires exactly three temperature entries (choice, score, noul), so a shared fitted temperature exports as `[T, 1.0, 1.0]`. Fit calibration NLL within the runtime's `[0.5, 5.0]` bounds and report a boundary optimum. Remove option-bucket/language overrides before applying the shared temperature; scope uses bucket `choice:6-10`, while the other four fields use `choice:3-5`. Per-question fitting needs both adequate support and a separately tested runtime change. Raw model-forward logits are unscaled; temperature applies during decoding. The current cached base has identity temperatures and empty buckets; record its actual configuration/hash.

The decoder rounds selected-option probability to four decimal places, which the worker forwards. Threshold selection and evaluation must use the same rounding and production projection to avoid cutoff differences. Full logits/probabilities for calibration and evaluation need a separate offline artifact path because the existing worker reply contains only the selected option/probability.

Precommit the abstention objective before looking at held-out outcomes. Required product choice: target definitive-label precision/risk and minimum useful coverage, with tie-breaking and uncertainty treatment. A reviewable proposed objective is maximize calibration coverage subject to a predeclared precision floor for definitive findings, then prefer the higher threshold on ties; no numeric floor is currently authorized. Small class counts may make that constraint impossible or unreliable. Report counts and confidence intervals; do not silently relax the floor. Calibration temperature and abstention threshold optimize different things and remain separately recorded.

Trace `MIN_DECISION_PROBABILITY` through `src/decision.ts` before implementing parameter loading: the current production projection uses a constant threshold, so a fitted threshold is not deployed merely by writing model configuration. Preserve scope/timing safeguards and the authoritative contract. Fit temperatures on calibration only and compute held-out output with frozen parameters. Calibration examples never enter optimizer updates, question revisions or rule changes.

## 6. Locked evaluation

Reuse `scripts/evaluate-laya-policy.ts` scoring/citation projection and production `interpretJob`, `applyDecision`, `mainDecision`, `LayaWorker`. Its present input loader explicitly accepts development data and appends authored diagnostics; do not call that existing run a held-out benchmark. Add a validated held-out path that requires source/capture/gold completeness and independent review, never appends development fixtures, pins all artifact hashes and claims a new immutable run slot before inference.

Its current expected schema contains vacancy outcomes rather than complete five-field passage gold. Extend the offline held-out schema to retain all five independent labels and source contexts while preserving separate restriction/headline expectations.

Lock test inputs and gold before tuning. Lock checkpoint, questions, calibration algorithm/parameters, threshold and projection before test execution. One registered final comparison includes deterministic rules, frozen base Laya, tuned uncalibrated Laya and tuned calibrated Laya using identical posting evidence and adjacent worker state. Include production hybrid only as an explicitly separate system. Run the base with its declared existing calibration and report that distinction; do not accidentally compare base-calibrated with tuned-double-calibrated predictions. Save raw probabilities for all five fields and final projected decisions. Model-only output has no citizenship/export restriction head: restriction results from deterministic rules must be attributed to that system.

Report per-field and per-class support, precision/recall and confusion matrices; exact five-field agreement; definitive error rates; calibrated NLL/Brier/reliability summaries; coverage and threshold-driven abstention; false/omitted blockers and incorrect definitive sponsorship; selected-option confidence; source-bound citation validity; latency; execution failures; extraction/completeness failures separately from interpretation errors. `unclear` as a predicted contract label is distinct from abstention caused by confidence below threshold. Report incomplete/silence/conflict/question/restriction slices and uncertainty intervals by independent employer/family groups. Tiny slices must show counts rather than a misleading percentage alone.

Never tune after seeing the locked report and reuse the same test as fresh evidence. A material fix or changed threshold requires a new independent test set and versioned decision. Permit a declared infrastructure-only retry only when no model outcomes/gold-driven changes were inspected; retain failed run metadata. Promotion remains a recorded gate requiring superiority over frozen base, no material regression on sensitive slices, valid citations and browser/service checks. A training completion flag is insufficient.
